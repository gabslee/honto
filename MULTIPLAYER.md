# Multiplayer Premium

## Starting a table

The lobby's Multiplayer switch is available only to the signed-in Premium host.
Guests may join without Premium or an account. Multiplayer supports 3–6 people;
the original mode remains exactly two people. The host can switch back only when
at most two people remain. Switching modes resets the card-type selection to the
appropriate deck; each customizable deck must contain at least three types.

Only the host starts a match. No new players may join after it starts, but an
existing room token can reconnect. Everyone submits a private wager and confirms
the welcome before the first card. Roles rotate after each card, including
Everyone Drinks and skipped cards.

## Guessing games

Two Lies, One Truth and Read My Mind collect one secret guess from everyone
except the author. Number Estimate provides three distinct numerical options,
generated by the server from the author's secret whole number (0–1,000,000),
and allows exactly one guess. Guessers cannot skip these cards.

All wrong guessers share a 1–3 sip wheel. The author has a separate wheel:

| Players | Correct guesses → author's wheel |
| --- | --- |
| 3 | 0: none; 1: 1–3; 2: 3–5 |
| 4 | 0–1: none; 2: 2–4; 3: 3–5 |
| 5 | 0–1: none; 2: 1–3; 3: 2–4; 4: 3–5 |
| 6 | 0–2: none; 3: 1–3; 4: 2–4; 5: 3–5 |

The author may skip before submitting their prepared card: an individual 2–4
wheel replaces the card. A submitted card cannot be canceled by its author.

## Voting

- **Would You Rather:** everyone, including the author, chooses A, B, or skip
  secretly. The minority shares a 1–3 wheel. Ties and unanimous valid votes do
  not incur a voting penalty. Each skip receives an individual 2–4 wheel and is
  excluded from the A/B counts.
- **Who at the table…?:** the deck supplies a themed prompt. Everyone votes for
  another player or skips. Self-voting is forbidden. Each player tied for the
  most votes gets an individual 1–3 wheel. Skips get individual 2–4 wheels.
  When everyone skips there is no additional voting penalty.

Answers remain private until everyone has responded. A missing response is not
silently converted into a skip.

## Challenges

- **Coin:** the author tosses a virtual coin. Heads selects the author; tails
  selects everyone. Selected players share one 1–3 wheel.
- **Staring contest:** the author chooses an opponent. Both confirm the same
  loser; disagreement clears the confirmations and repeats the duel. The loser
  gets a 1–3 wheel. An opponent may decline before participating for 2–4 sips,
  ending the card.
- **Joken-pô:** an occasional duel within Challenges, not a separate group card
  type. Moves are secret; a tie repeats the duel. The loser gets a 1–3 wheel.
  An opponent can decline before submitting a move for 2–4 sips.
- **Surprise:** everyone answers yes/no to the same prompt. Answers reveal
  together. Each yes receives an individual 1–3 wheel. No yes means no wheel.
- **Everyone Drinks:** everyone shares a 1–3 wheel. This consumes a normal card
  and advances the turn.

All wheels require an explicit spin. Individual wheels can run concurrently;
any affected player may spin a shared wheel. Replayed spins cannot score twice.
The server enforces the 6.5-second animation interval before accepting Continue.
Every remaining player confirms Continue before the next card appears.

## Departures and the end of the match

An absent player can reconnect with their existing session. The host can remove
someone who has left, after explicit confirmation. Removing a participant
releases their pending response/wheel/continuation requirements. If the author
or duel opponent leaves before the result, the interrupted card ends without a
new penalty. Fewer than three remaining players ends the multiplayer match;
it never silently converts into a two-player game.

Host controls transfer when the host leaves. An already-started game continues
without rechecking Premium for each move. Starting another multiplayer match
requires a Premium host again.

The lowest sip total wins. A unique winner's wager is assigned to the last-place
player(s), including a tie for last place. A tie for first place has no mandatory
wager. Ending early because too few players remain does not crown a winner.

## Implementation and validation

- `api/multiplayer.ts` is a pure immutable rule engine and privacy projection.
  Its complete snapshot is private; clients never receive future cards or
  another player's unrevealed choice.
- `api/game.ts` authenticates room tokens and Premium host identity, then
  persists the snapshot through PostgreSQL revision comparisons. A single SQL
  statement commits dependent mutations. Concurrent writes retry against fresh
  state. The server owns randomness, results, scores, and eligibility.
- The existing `rooms`, `players`, and `deck_cards` PostgreSQL schema stays in
  place. Additive multiplayer columns leave existing two-player matches intact.
  Runtime initialization applies the same additive changes as the migration.
- Group scores live in the versioned snapshot. Existing player rows own room
  membership, account binding, and wagers; the API composes the public view.
- `data/multiplayer-prompts.ts` contains matching English/Japanese prompts for
  general, life, relationships, and Premium spicy themes.
- Run `npm run test:unit` for rules, complete-match journeys, lobby access,
  rendering, privacy, persistence, and session tests. Run `npm test` to include
  the production build. Use Node 22.18+ within the project's Node 22 series.

Question or Sips remains available in two-player mode and is excluded from the
multiplayer deck. Newly generated authored text remains authored content.
